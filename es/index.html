Cómo decodificar texto Base64 en línea

Decodificar Base64 recupera los bytes representados por una cadena. Este decodificador los interpreta como UTF-8 para mostrar texto, incluidos acentos y emojis. Sirve para revisar valores de API; no descarga imágenes ni PDF.

  1. Pega solo la parte Base64. Elimina las comillas de JSON o prefijos como data:text/plain;base64, antes de convertir.
  2. La conversión es automática. Si la desactivas, pulsa el botón de conversión o Ctrl+Enter (⌘+Enter en Mac).
  3. Copia el resultado con el botón de copia. El límite es de 5 MB de texto UTF-8.

Formatos Base64 y relleno admitidos

Base64 usa + y /; Base64URL usa - y _. Las letras y los números se mantienen. El relleno = es una decisión independiente: algunos protocolos lo omiten y otros lo conservan. Una cadena formada solo por letras y números no permite distinguir los dos alfabetos. Ninguno de los formatos es un cifrado.

Cada carácter de datos representa seis bits. Tres bytes completan 24 bits y cuatro caracteres. Los acentos y emojis pueden ocupar varios bytes UTF-8: 😀 ocupa cuatro bytes y produce 8J+YgA==. La tabla compara entradas de uno, dos y tres bytes.

Zg → f; Zg== → f; 8J-YgA → 😀.

Resolver errores de decodificación Base64

Si una cadena no se convierte, elimina comillas, signos adicionales y el prefijo de una URL de datos; pega solo la parte Base64. El relleno = solo puede aparecer al final. Una longitud con resto 1 al dividir entre 4 es inválida. Los espacios, saltos de línea y caracteres de Base64URL - y _ se aceptan. Un error UTF-8 puede indicar datos binarios o una codificación distinta: UTF-8 es el valor predeterminado. Si el texto es ilegible, elige la codificación original.

Preguntas frecuentes

¿Por qué el texto aparece ilegible o da un error UTF-8?

Comprueba la codificación original. Base64 no indica si los bytes son UTF-8, otra codificación o datos binarios. Este decodificador no convierte automáticamente EUC-KR ni Shift_JIS. Añadir = no corrige ese problema.

¿Toda cadena Base64 termina en =?

No. Si el número de bytes es múltiplo de tres, no se necesita relleno. Otros protocolos omiten el relleno expresamente.

¿Base64 protege mi texto?

Base64 es una representación reversible de datos, no un cifrado. No protege contraseñas ni otros secretos.
