Décoder du texte Base64 en ligne

Le décodage Base64 restitue les octets représentés par une chaîne. Ce décodeur les lit en UTF-8 pour afficher du texte, avec accents et emojis. Il permet de vérifier des valeurs d’API, sans télécharger d’images ou de PDF.

  1. Collez uniquement la partie Base64. Retirez les guillemets JSON et les préfixes tels que data:text/plain;base64, avant la conversion.
  2. La conversion est automatique. Si vous la désactivez, utilisez le bouton de conversion ou Ctrl+Entrée (⌘+Entrée sur Mac).
  3. Copiez le résultat avec le bouton de copie. La limite est de 5 Mo de texte UTF-8.

Formats Base64 et remplissage acceptés

Base64 utilise + et / ; Base64URL utilise - et _. Les lettres et les chiffres restent identiques. Le remplissage = dépend du protocole : il peut être conservé ou omis. Une chaîne uniquement alphanumérique ne permet pas de distinguer les deux formats.

Un octet restant exige == ; deux exigent = ; trois n’en exigent aucun. f donne Zg==, fo donne Zm8= et foo donne Zm9v. Comptez les octets UTF-8, car une lettre accentuée ou un emoji peut occuper plusieurs octets.

Zg → f; Zg== → f; 8J-YgA → 😀.

Résoudre les erreurs de décodage Base64

Si une chaîne ne se décode pas, retirez les guillemets, signes superflus et préfixes d’URL de données ; collez uniquement la partie Base64. Le remplissage = ne peut apparaître qu’à la fin. Une longueur dont le reste de la division par 4 vaut 1 est invalide. Les espaces, sauts de ligne et caractères Base64URL - et _ sont acceptés. Une erreur UTF-8 peut indiquer des données binaires ou un autre encodage : cet outil accepte uniquement du texte UTF-8.

Questions fréquentes

Pourquoi le texte est-il illisible ou signalé comme UTF-8 invalide ?

Vérifiez l’encodage d’origine. Base64 n’identifie ni UTF-8, ni un autre encodage, ni des données binaires. Ce décodeur ne convertit pas automatiquement EUC-KR ou Shift_JIS. Ajouter des = ne résout pas ce problème.

Une chaîne sans = est-elle toujours incorrecte ?

Non. Les données dont la taille est un multiple de trois octets n’exigent pas de remplissage. Certains protocoles le suppriment également.

Base64 protège-t-il mon texte ?

Base64 est une représentation réversible des données, pas un chiffrement. Il ne protège ni les mots de passe ni les autres secrets.
