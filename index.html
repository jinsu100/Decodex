Encoding, explained

Base64 represents data as text. It is not encryption and doesn't keep sensitive information secret.

How to decode Base64 text online

Base64 decoding restores bytes from a text representation. This online decoder reads those bytes as UTF-8 to display readable text, including Korean and emoji. Use it to inspect an API value or a copied string. It is a text converter rather than a tool for downloading image or PDF files.

  1. Paste the Base64 value into the input box. Remove surrounding JSON quotes or a prefix such as data:text/plain;base64, and keep only the encoded portion.
  2. Conversion is automatic as you type or paste. Turn off Auto convert to use the button or Ctrl+Enter (⌘+Enter on Mac).
  3. Use Copy result to copy the output. The UTF-8 input or decoded data limit is 5 MB (5 × 1024 × 1024 bytes).

Supported Base64 formats and padding

Standard Base64 uses letters, digits, + and /. Base64URL uses the same letters and digits but replaces + with - and / with _. Padding is a separate decision: Base64URL may include =, or a protocol may specify its omission. A string containing only letters and digits cannot tell you which alphabet the sender intended.

Each Base64 data character represents six bits. Three bytes supply 24 bits, which fit four characters exactly. With one remaining byte, two data characters are followed by ==. With two remaining bytes, three data characters are followed by =. Padding fills the output group; it does not add bytes to the decoded result.

Zg → f; Zg== → f; 8J-YgA → 😀.

Fixing Base64 decoding errors

Whitespace and line breaks are ignored, and omitted padding is restored. Misplaced or partially supplied padding is rejected: Zg decodes to f, but Zg=, A=AA and Zg=== fail. A whitespace-free length with remainder 1 when divided by 4 is invalid. If a URL changed + to a space, or part of the value was truncated, check the original source.

Frequently asked questions

Why is the decoded text garbled or reported as invalid UTF-8?

Check how the original text was encoded. Base64 does not identify a character encoding. EUC-KR, Shift_JIS and binary image or PDF data may not display correctly in this UTF-8 text decoder. Adding more = characters does not solve a character encoding problem.

Can an encoded string have no =?

Yes. If the byte count is a multiple of three, padded Base64 needs no =. Some protocols also deliberately omit padding from incomplete final groups.

Does Base64 protect my text?

Base64 is a reversible representation of data, not encryption. It does not protect passwords or other secrets.
